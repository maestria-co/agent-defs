## Entry: Fix Manager Agent Task Classification Logic (MJE0005)

**Date:** 2025-01-13  
**Agent(s) involved:** Manager, Coder  
**Outcome:** ✅ Success

### What happened
The Manager agent's task classification logic was using subjective "simple vs complex" rules to decide whether to create task files. This led to agents skipping task infrastructure on medium-complexity work, causing context loss during handoffs. The solution replaced subjective rules with a deterministic 4-trigger system: any task requiring (1) multi-agent coordination, (2) cross-system changes, (3) database/schema changes, or (4) user-facing behavior changes now always gets a task file.

### What worked well
- The new trigger-based system is objective and easy to apply
- Clear criteria remove ambiguity about when to create task infrastructure
- Documentation updated in both agent prompt and skills

### What didn't work / what was surprising
- Previous "simple vs complex" language was too vague and led to inconsistent behavior
- The impact wasn't obvious until multiple agents lost context mid-task

### What should change
- **Rule:** Manager agent now uses deterministic triggers instead of subjective complexity assessment
- **Pattern:** Any task meeting one of the four triggers gets full task infrastructure (task file + structured handoffs)
- **Who should act:** This is already implemented in the Manager agent prompt and `creating-tasks` skill
